# 装甲击打检测模块（Armor_Cmzy26_081）固件总体设计方案

版本：v1.5　|　日期：2026-08-21　|　适用硬件：SCH_Armor_Sc_EVE_081（硬件版本 080/081）　|　MCU：STM32L432KBU6（80MHz，裸机 HAL + Makefile，无 RTOS）

## 0. 方案基线

- **本板定位**：车队自研"车内总线"节点，**不直连官方裁判系统**。只与车队裁判核心板通过 CAN 500kbps 固定帧通信，协议见 `Docs/CAN_PROTOCOL.md`。官方装甲模块的协议与语义仅作**功能需求参考**（第 1 章），**不追求官方协议兼容**。
- **引脚/硬件定义以 CubeMX（`Armor_Cmzy26_081.ioc`）配置为准**，原理图仅作参考（原理图个别标注有误，见 2.3）。
- **时钟前提（已确认）**：HSE=8MHz（外部振荡器；原理图标注"12MHz"有误），PLL M=1/N=20/R=2 → **SYSCLK=80MHz**（AHB/APB1/APB2 不分频），当前 `.ioc` 配置正确，无需修改。
- **通信协议栈（2026-09-06 起）**：不引入第三方栈，通信层自研固定帧实现（`App/comm/app_can.c` + `can_node.c` + `board_comm.c`，见第 9 章与 `Docs/CAN_PROTOCOL.md`）。原 ISO-TP 栈方案（`Driver_Examples/stm32-referee-isotp-stack`，无 LICENSE 的风险记录见 R5）已弃用，仅作历史参考。
- **文档依据**：CubeMX 工程（.ioc + 生成代码）、`Docs/ads131m04.pdf`（SBAS890D）、RM0394（STM32L4 参考手册）、RM2025 裁判系统用户手册 V1.4、AM02&AM12 / AM01&AM11 使用说明书（后三者仅取功能语义）。

### 1.2 其他需求与约束

- 供电：裁判系统 6 脚连接器提供 12V（经 0.25A 保险丝），**信号线仅 CANH/CANL 两根**，其余为电源引脚；板载多级电源（见 2.2）。**不考虑硬件负载能力约束**。
- 环境：赛场环境（振动、温漂、弹丸连发 ≤20Hz），检测需抗慢按压/扶板误报。
- 软件约束：CubeMX 生成工程（重生成会覆写生成文件），遵循修改优先生成文件原则，所有手写代码须在 `USER CODE BEGIN/END` 块或独立目录 `App/` 中。
- **保护阈值默认原则**：类似温度保护的阈值（超温、电源等）**默认取最宽松/最大值**，确保开发测试阶段保护不触发、可先验证后续功能；标定/联调后再收紧（P19/PVD，见 7.4/7.5）。

### 2.2 模拟前端与电源

- **信号链**：4× 全桥应变片（连接器 U3~U6，SC_REF_OUT 2.5V 激励）→ 共模电感滤波 → 4× INA826AIDR 仪表放大器（RG=5.1kΩ 0.1%，G≈10.7）→ 10Ω 串联 + 100pF/1µF 滤波 → ADS131M04 的 AIN0~AIN3。
- **差分输入拓扑（已确认）**：**BIAS1_OUT 是 INA826 输出电压的直流偏置，接到 ADC 四个通道的 N 端**；各通道 P 端接对应放大器输出。即 ADS131M04 差分输入 = 放大器输出（P）− BIAS1_OUT 直流偏置（N）。**各通道的实际极性还受传感器接线方式影响**，固件以"极性宏 + 开机击打校对"处理（见 6.7）。
- **电源树**：12V（保险丝 0.25A）→ LMR54410 降压 5VD → HT7133 LDO 3.3VD（数字）；5VD → LM7805 5VA → LT3042 超低噪声 LDO 3.3VA（模拟，ADS131M04 AVDD 与前端）。REF5025×4 提供 2.5V 电桥激励，其 TEMP 脚接 STM32 ADC 供温度监测（超温告警源）。
- **CAN**：TJA1044GTK → 共模电感 → 裁判系统 6 脚连接器（信号线仅 CANH/CANL 两根）。
- **灯**：板载 1 颗 WS2812（GL5050RGB01H-T，DIN=PA2），DOUT 级联到外部灯带连接器 CN1（左右装甲板各 6 颗，共 13 颗，见 8.1）；板载 LED1/LED2 各串 510Ω 接 PB0/PB1（**高电平点亮**，硬件实测确认 2026-08-21）。

### 3.1 分层结构

```

├─────────────────────────────────────────────────────────────────────┤

│            detect/calibration.c（参数表 + 标定 + 极性校对 + Flash 持久化）│

├─────────────────────────────────────────────────────────────────────┤

├─────────────────────────────────────────────────────────────────────┤
│  BSP 层     bsp/ads131m04.c（SPI+CS+DRDY+SYNC、寄存器访问、DMA 帧读） │
│            bsp/ws2812_uart.c（USART2+DMA 灯带驱动）                   │
│            bsp/temp_mon.c（ADC1 TIM1 触发式 TEMP 采集 + 窗检）        │
│            comm/app_can.c（HAL CAN 绑定：FIFO0 中断收 / 邮箱发）      │
│            comm/app_log.c（USART1 调试日志，可选）                    │
├─────────────────────────────────────────────────────────────────────┤
│  硬件层     CubeMX 生成骨架（Core/Src + HAL 驱动 + 裸机外设）          │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 数据流

```
上行：弹丸/碰撞 → 4×全桥应变片（差分 mV 级）
     → 4×INA826（G≈10.7）→ ADS131M04 4 通道 24bit ΔΣ（内部 VREF=1.2V）
     → SPI1 Mode1 @5MHz，6 字=18B/帧，DRDY(PA15) 下降沿触发（方案 A）
     → bsp/ads131m04.c（DMA 帧读取，极性宏取反，STATUS 字健康位检查）
     → detect/hit_detect.c（基线 EMA→高通→差分→阈值/持续判定→锁帧→窗口确认→50ms 不应期）
     → 击打事件（通道/强度/力度/时间戳）
     → comm/board_comm.c（固定 ID 帧：0x130+(NodeID−1)×0x10+offset）→ app_can.c
     → TJA1044GTK → CAN 500kbps → 裁判核心板（车内总线）

下行：核心板命令 → CAN FIFO0 ISR → 小帧入队 → 主循环业务 ID 分发
     → LED 控制 / 状态回复 / NodeID 身份回复 / 击打 ACK
```

### 3.3 实时性关键路径

- 采集速率：fDATA = **3.906kHz**（CLKIN=8.0MHz → fMOD=4.0MHz ÷ OSR 1024），帧周期 256µs。
- 击打事件端到端时延（**2026-10-16 起为两段式判定，指标由 <3ms 放宽至 ≈18ms**）：DRDY → EXTI 启动 DMA（<2µs）→ 帧就绪（28.8µs@5MHz）→ **第一段触发判定**（|hit_dif| 连续 P03=4 样本 ≥1.02ms）→ **第二段确认窗**（等满 P22=64 个触发后样本 ≈16.4ms，见 7.1）→ 判定（两遍 O(128) 特征扫描 + 一遍 O(128) 归一化相关，纯整数 <15µs）→ 入队 → CAN 发送（邮箱空时 <100µs，繁忙时 ≤2ms）。**总时延 ≈18ms**（训练那一击额外有 ~6ms Flash 编程，落在 50ms 不应期内，不影响上报时延）。
  - 放宽依据（2026-10-16 决策）：确认段必须在**触发后完整窗口**上做后分析才能区分"检测模块本体震荡"与"真正打在受击面的击打"；旧 <3ms 指标对应的是"一触发就上报"的单段版本，该版本无法做此区分。
  - 触发间隔下限：最小触发间隔 = 确认窗 16.4ms + 不应期 P05=50ms ≈ **66ms**（≈15Hz 上限；2026-10-16 窗口取上限后由 58ms 增大）。两发相隔 <66ms 的连击会被合并为一次上报；若判定需要恢复 20Hz 口径，把 P05 下调到 ≈34ms 即可——不应期只需覆盖冲击余振衰减，确认窗已单独占用 16.4ms。

### 4.1 TIM16 CLKIN 频率：8.0MHz（HR 模式，跑满）

- **决策依据（用户确认）**：ADS131M04 内部有 sinc3 数字低通滤波与可编程 OSR，**无需顾虑器件电流，时钟性能跑满**。
- 配置：TIM16 PWM 8.0MHz（ARR=9、CCR=5，50% 占空）→ CLKIN=8.0MHz → HR 模式（CLOCK.PWR=10b，恰为复位默认）→ fMOD=4.0MHz，OSR=1024（默认）→ **fDATA=3.906kHz**（帧周期 256µs）。
- 注记：8.0MHz 相对标称 8.192MHz 偏差 -2.3%（80MHz 无法整数分频出 8.192×k），fDATA 相应偏移，判定参数均按样本数/时间双标定；**M1 实测 DRDY≈3906Hz 确认**（风险 R7）。
- 如需更高数据率：OSR 可降 512/256（fDATA 7.8k/15.6k），由参数表支持运行时改（P20）。

### 4.2 时钟树

## 6. ADS131M04 驱动设计

### 6.1 关键接口事实（SBAS890D）与平台硬件能力（RM0394）

**ADS131M04 接口事实**：

- SPI **Mode 1**（CPOL=0/CPHA=1）；SCLK ≤25MHz（DVDD≥2.7V）；CS 跳变须在 SCLK 低电平；DIN 下降沿采样、DOUT 上升沿更新。
- 字长 16/24/32 可配（MODE.WLENGTH），**默认 24 位**；命令/寄存器响应恒为 16 位有效数据、MSB 对齐、低位补零。
- M04 每帧 **6 字** = 状态字 + 4 路数据 + CRC 字（默认关）；全双工，**响应在下一帧出现**；RESET 命令在整帧完成后才锁存。
- CLKIN 须持续提供；fMOD=fCLKIN/2，fDATA=fMOD/OSR；OSR 8 档（128~16384，默认 1024）；**内部 sinc3 数字低通滤波**。
- DRDY 低有效、默认电平式（数据可用拉低、读走整帧后拉高）；每通道 2 深 FIFO，>2 个采样周期未读会丢沿；**无 CS↔DRDY 对齐要求**，避免在新转换完成瞬间读取即可。
- 数据 24 位二进制补码，满量程差分输入 = ±1.2V/Gain（内部 VREF=1.2V）；GAIN1 每通道 1/2/4/8/16/32/64/128 八档。
- 命令：NULL=0x0000、RESET=0x0011、STANDBY=0x0022、WAKEUP=0x0033、LOCK=0x0555、UNLOCK=0x0655、RREG=0xA000|addr<<7|n、WREG=0x6000|addr<<7|n。
- POR 后等 DRDY 由低到高（接口就绪）方可通信；复位后寄存器回默认并解锁。
- **CS 定界语义**：CS 上升沿复位/重同步 SPI 接口；**支持 CS 常低连续帧**（MODE.TIMEOUT 提供失步恢复，帧须在 32768 tCLKIN=4.1ms@8MHz 内完成）；8-bit×3 分块收发可行（接口按 SCLK 边沿计数，字节边界无关）。

**STM32L432 平台能力（RM0394，决定读取方案）**：

- **无 DMAMUX**（L4+ 才有），DMA 请求固定映射：SPI1_RX=DMA1_Ch2（或 DMA2_Ch3）、SPI1_TX=DMA1_Ch3（或 DMA2_Ch4）、USART2_TX=DMA1_Ch7、TIM2_UP=DMA1_Ch2（与 SPI1_RX 同通道冲突）。
- **无 EXTI→DMA 直连**：DRDY 触发读取必经 CPU EXTI 中断启动（硬件事实）。
- SPI 数据宽 4~16bit（无 24bit 档）；TIM DMA burst（DCR/DMAR）只能写定时器自身寄存器，**不能写 SPI1_DR**；TIM2_UP 可作为普通 DMA 请求周期写 SPI1_DR。

### 6.3 初始化序列（**REVID=0x05 实测修订：MODE 不写、其余寄存器按开关写入**）

> ⚠️ 2026-08-21 实测：本板芯片 ID=0x2405（REVID=0x05），寄存器布局与 SBAS890D（REV A）手册不一致——**写 MODE（旧布局值）会把字长清成 16 位模式**，导致帧流错位（MODE 的 WLENGTH 位控制 SPI 帧字长，写坏即整链失步）。MODE 复位默认 0x0510 即目标配置，**初始化默认不写 MODE**。
> ⚠️ 2026-09-09 批次发现：新批次芯片复位后 CLOCK 默认回读 **0x0F02**（旧批次 0x0F0E），疑似默认 OSR 不同。因采样率参数不可改，恢复寄存器写入能力：`ADS_REG_INIT_ENABLE`（默认 1）按 6.2 表写入除 MODE 外全部寄存器（**CLOCK 排第一**，写入失败只记日志不判初始化失败，实际数据率由上电自检 ST_DRDY 行为关卡判定）；`ADS_REG_INIT_WRITE_MODE`（默认 0）为 MODE 写入实验子开关。任何写坏由每次上电的 RESET 自愈序列兜底恢复。详细过程见 `Docs/ADS131M04_初始化SPI时序.md` 第 10 节。

1. 上电延时 50ms（12V→多级 LDO 电源建立）。
2. **PC15 复位脉冲 12.5µs**（复位窗口 8~2048 tCLKIN=1µs~256µs@8MHz；**超过 256µs 会被解释为"转换同步"而非复位**——不可用 ms 级延时）后拉高。
3. **自愈盲发序列**（2026-09-09 前移）：UNLOCK → NULL → RESET → NULL——坏状态芯片（16bit/LOCK/低功耗、DRDY 卡低）接口早已就绪，RESET 保证被解码（"命令+NULL"两拍下命令槽自对齐，LCM(144,96)=288 位）；刚 POR 的芯片在未就绪窗口内忽略该序列，无害。
4. 等待 **DRDY 上升沿**（POR 后可通信标志），超时 100ms → 判"传感器无响应"故障（含 4 帧 NULL 诊断 ping 打印 MISO）。
5. **就绪后补发 RESET**（双保险）：UNLOCK → NULL → RESET → NULL → 再等 DRDY 上升沿——保证第一发若被未就绪窗口忽略时 RESET 仍落地。
6. 发 UNLOCK（0x0655）——显式防异常状态。
7. **探针读回验证**：ID（期望 0x24xx）、MODE（期望 0x0510=24bit）、CLOCK（期望 0x0F0E/0x0F02，批次差异）——任一不符 → 上电自检失败。
8. **寄存器表写入**（`ADS_REG_INIT_ENABLE=1` 时）：按 6.2 表顺序写入并回读校验（CLOCK 优先；MODE 默认跳过），逐条打日志，写后复探 CLOCK；失败不判初始化失败。
9. **丢弃前 2 帧**（器件响应延迟一帧，首帧为旧数据），进入正常采集。

### 6.4 帧读取方案（分析 + 结论）

#### 方案 A（已确认采用）——DRDY 外部事件触发 + SPI DMA

- 流程：PA15 DRDY 下降沿 → EXTI15_10 ISR：取**K 帧环形缓冲**的下一个空闲槽（槽满则跳过本帧并 drop 计数）→ 拉低 CS（PC14 GPIO）、启动 `HAL_SPI_TransmitReceive_DMA`（TX=静态 18B NULL 缓冲 → DMA1_Ch3；RX=写入该槽 18B ← DMA1_Ch2）→ SPI TX/RX 完成中断：拉高 CS、槽标记满 → 主循环按读指针消费帧并喂检测管线。
- 环形缓冲：默认 **K=32**（32×18B=576B，预触发历史 8.2ms）；写指针仅 ISR 侧修改、读指针仅主循环侧修改、槽状态用原子标志（风险 R17）；drop 计数纳入 1Hz 诊断快照（`s_rate_drop`，见 10.2）。
- 软件参与度：每帧 2 个轻量 ISR（共 ~2µs）@3.906kHz ≈ **0.8% CPU**；SPI 收发全程 DMA（18B@5MHz=28.8µs 后台完成，占采样周期 11.3%，CPU 零负担）。寄存器读写利用帧间隙：暂停采集 → UNLOCK → WREG/RREG → LOCK → 恢复后丢弃 2 帧重同步。
- 为什么 L432 上 EXTI ISR 不可避免：**L432 无 DMAMUX、无 EXTI→DMA 直连**，DRDY 触发读取只能经 CPU 中断启动（RM0394 查证）。
- 优点：可靠、易调试、与寄存器读写天然兼容；DRDY 电平式天然防过读（读走整帧才拉高）。

##### 帧缓冲深度分析（双缓存是否有必要）

1. **当前击打检测需求：双缓存不必要。** 单缓冲 + 消费门控即可零撕裂——DRDY 为电平式（读走整帧才拉高）且每通道有 2 深 FIFO：消费未完成时不启动下一帧 DMA，帧序不乱、无撕裂，偶发跳帧不影响阈值判据（主循环负载 5-6%，阻塞 >256µs 概率极低）。
2. **双缓存（ping-pong）只比单缓冲多容忍 1 帧滞后**（256µs → 512µs），对"精确连续采样"帮助有限。
3. **弹速/入射角反推（7.8）真正需要的是 K 帧环形缓冲 + 触发时波形冻结**：事件窗口内零丢帧、预触发历史（冲击上升沿在阈值触发之前）、触发后衰减窗口。因此方案 A 直接采用 K=32 环形缓冲（成本 576B RAM，可忽略），一步到位满足未来需求，无需后续返工。

#### 方案 B（备选分析留存，不实现）——周期自动 SPI+DMA，零每帧 CPU

- 原理：**TIM2_UP 作为 DMA 周期请求**（L432 支持）驱动采集流水线：
  - SPI1 改 **16-bit** 数据宽；TIM2_UP @ **35.156kHz（=9×fDATA）** → DMA1_Ch2（circular，NDT=9，静态 0x0000 字）逐字周期写 SPI1_DR——每帧 9×16bit=144 SCLK，5MHz 下 28.8µs 活跃；
  - SPI1_RX → **DMA2_Ch3**（避开 Ch2 冲突）circular 36B 双缓冲，半传输/传输完成中断各报告一帧（HT/TC 天然 ping-pong）；
  - **CS 常低**（PA15 恒输出低）：ADS131M04 支持 CS 常低连续帧，帧长 256µs ≪ MODE.TIMEOUT 4.1ms，无超时风险；TIM2 与 CLKIN（TIM16）同源 80MHz，**采集速率与 fDATA 相位锁定、无漂移**。
- 软件参与度：仅 HT/TC 中断置标志（~0.1% CPU），无每帧 CS/DMA 操作。
- 限制与前提：① CS 常低按字计数定帧的行为手册未明引（M1 需实测验证，风险 R16）；② 寄存器读写需停机（暂停 DMA/TIM）→ 读写 → 重启 → 重同步；③ TIM2 被占用 → 1kHz 状态时基需改用 **TIM15**（16-bit，Prescaler=3、ARR=19999 → 1kHz）。
- 结论：作为 M1 之后的**可选零 CPU 优化**评估，不进入首版实现。

#### 硬件 NSS 分析结论：不可用，保留软件 CS


| 硬件 NSS 模式 | 行为（RM0394）                                                         | 对 ADS131M04 的影响                                                           |
| --------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| SSOE=1        | NSS 在 SPE=1 全程保持低，SPE=0 才拉高（§41.4.5）                      | 无帧边沿，无法定界每帧 6 字                                                   |
| NSSP=1        | 仅 CPHA=0 时有效（§41.4.12），且 8-bit 数据宽时每 8 SCLK 打一个高脉冲 | ADS 要求 CPHA=1 → NSSP 直接失效；即使可用也会在 24bit 字中间打脉冲破坏字同步 |

故**片选用 PC14 GPIO 软件控制**（CS 跳变在 SCLK 空闲低电平时进行，满足规格）。当前 .ioc 中 PC14=ADC_CS（GPIO 输出）、PA15=ADC_NDRDY（EXTI 输入），软件 CS 方案已就位。

### 6.5 寄存器读写 API 与错误处理

- `RegRead` = RREG 帧 + NULL 帧两拍；`RegWrite` = WREG（命令字+数据字）帧 + RREG 回读校验（6.3 全部寄存器均走此路径）。
- 帧级错误：HAL/DMA 超时/参数错 → 计数并丢弃本帧；开启 CRC 后第 6 字按 CCITT-16 校验前 5 字，错则 `crc_err++` 丢弃。
- 状态字健康位每帧检查：REG_MAP 异常、CRC_ERR、RESET（意外复位）、LOCK 位与预期不符 → 置故障位。
- 诊断计数（spi_err/crc_err/drdy_cnt）纳入 1Hz 诊断快照（`s_rate_*`，见 10.2）与调试变量表。
- 中断归属：`ADS131M04_IrqDrdy()` 挂 EXTI15_10；`ADS131M04_IrqDmaDone()` 挂 SPI1 全局中断与 DMA 中断回调。

### 6.6 增益档位（GAIN1）

- **量产版定稿（2026-09-09）：4 通道 PGA=8×**（GAIN1=0x3333，写入见 6.2 表）。补偿公式：外部传感器 0.25 × 外部前端 0.5435 × 片内 PGA 8 = **1.087**——与旧版信号水平基本一致，击打阈值/力度标定参数维持有效，8.7% 偏差由 M2 两点标定吸收。
- 初始 Gain=1 的历史决策（灵敏度未知前保证最大头屋，490N 满程 ~54mV 仅 4.5%FS）已被量产版硬件确认取代；新链满程估算 ≈4.9%FS，饱和裕量充足。
- GAIN1 每通道 3bit 可独立配置（1/2/4/8/16/32/64/128），P17 参数表 `gain1[4]` 与硬件一致（默认 8）。
- 噪声预算：用户判定噪声主要来自 ADC 本身（PGA 8× 不放大 ADC 自身噪声 counts）；旧版 24~30 LSB@Gain=1 的实测噪声被 INA826 输出噪声主导的结论在 0.5435× 前端下需台架复核（自检 RMS 门限 1~50 维持不变）。

### 6.7 通道极性处理（宏定义 + 开机校对接口）

- **极性宏**：`App/board.h` 定义 `#define ADC_CH_SIGN_MASK 0x00`——bit0-3 对应 ch0-3，**1=该通道取反**（BIAS1_OUT 接 4 通道 N 端，各通道极性最终取决于传感器接线方式）。驱动层按宏对帧数据取反（`ch[i] = -ch[i]`），上层不再感知；运行时可经 `ADS131M04_SetChannelSign(mask)` 覆盖（从 Flash 标定值恢复）。
- **开机击打校对接口（预留）**：`int HitDetect_CalibratePolarity(void)`——开机/自检时经一次**已知方向**的击打（或 DAC 注入已知符号激励），校验 4 通道响应符号，与预期不符的通道自动写入符号掩码并持久化到 Flash。接口在 M1 定义、M2 落地完整流程；在标定完成前极性以宏初始值运行。

## 7. 击打检测算法设计

输入：4×int32（符号已按 6.7 修正），**3.90625kHz**（dt=0.256ms）。

**四传感器融合模型**：4 个通道对应 4 个传感器，构成完整检测模块；**传感器在受击平面上中心对称分布**。弹丸击打不一定打在击打平面中心，一次击打会在 4 通道上**同时**产生响应，且**强度随击打位置分布**（离击打点近的传感器分力大）。因此检测按"单模块融合"设计：以四通道分力之和（合力）作为判定信号，**单次击打全局只产生一个事件**。

### 7.1 处理管线（M2 修订：差分级联触发 + 锁帧后确认，两段式判定）

```
各通道：raw → [基线 EMA：bl += (raw-bl)>>13，τ≈2.1s] → hp = raw - bl
    → 合成：hit_sum = Σhp(ch)（四通道分力之和，即合力信号）
    → 【差分高通】hit_dif[n] = hit_sum[n] − hit_sum[n−M]（M=P25 dif_depth，
        默认 16 样本=4.1ms，截止 ≈39Hz）——仅用于触发判定

——— 第一段【触发】（保持原样，不参与真伪判定）———
    → 判定：|hit_dif| ≥ P04 THR_HIT 且持续 ≥P03 样本（1.02ms）
    → 锁帧：快照波形环的预触发 P21 样本（触发样本落在索引 P21−1）

——— 第二段【确认】（2026-10-16 新增：等满 P22 触发后样本后执行一次）———
    → 对冻结窗合力序列与**参考样本**做归一化互相关：corr_q10 = |ρ|×1024（判据见下）
    → 拒绝 → 丢弃：不成事件、不上 CAN、不打灯，只留相关度供台架整定
    → 接受 → 填事件（峰值分布/时刻/半高脉宽/冲量）→ 入队 → CAN 上报
             且若为本次上电第一次接受 → 该冻结窗固化为参考并写 Flash（末页 2KB）
    → 两条路都进 50ms 不应期（自确认完成时刻起算）→ P26 沉降门控 → 重新武装
```

> **参考样本判据的由来（2026-10-16 决策）**：确认段最初的实现扫四个启发式特征
> （通道均匀度 / 预触发能量占比 / 占空比 / 滞回过零，P27~P31），台架证明**它们没有
> 实质性区分"壳体震荡"与"真实击打"**——上述四项在两类的取值区间大面积重叠。改为
> **与参考样本做归一化互相关**：上电后第一次正常击打的锁帧样本写 Flash 作为参考，
> 此后逐次比对形状。四项启发式已完全移除（含 `hit_reject_t` 记录机制）。
>
> 归一化的意义（**必须**）：相关按 Pearson（归一化互相关）算，分子除以两窗标准差之积，
> **结果与幅值完全无关**——同一位置 19N 与 100N 击打形状相同则 ρ 都趋近 1，纯幅值缩放
> 不改变 ρ。力度信息不因此丢失：它由事件字段 `force_01n/intensity`（K_N 标定路径）承载，
> 相关只管形状。落地方式分两处：**训练时**把参考固化为"去均值 + 预计算平方和"
> （`s_ref_c[]` / `s_ref_norm`），**每次判定时**对新窗做同样处理再算
> `ρ = Σdx·c / (√Σdx² · √Σc²)`（两部分开开方，避免 64 位相乘溢出）。

- **基线漂移补偿**：每通道独立 EMA，α=2^-13（dt=0.256ms → τ≈2.1s），跟踪安装形变、温漂、重力姿态变化（装甲板翻转时直流偏置随之变化属正常）；整数移位实现，零除法零浮点。
- **高通**：`hp = raw − bl` 即一阶高通（截止 ~0.076Hz），剔除直流分量。
- **差分高通（M2 修订，关键）**：`hit_dif[n] = hp[n] − hp[n−M]`——一阶 EMA 高通压不住 0.1~10Hz 的低速摆动/姿态瞬态（实测导致静止误报）；差分级对该频段衰减 ≈−39dB（1Hz 处），100Hz 冲击边沿无损（≈×1.9 增益），真实击打（≈30 万 counts 量级）完整保留，静止噪声 ×√2≈70 counts 对 2 万阈值余量 280 倍。
- **通道融合**：`hit_sum = Σhp(ch)`（合力）——中心对称布局下合力与击打位置无关，天然保证"一次击打=一个事件"；50ms 不应期作为防抖辅助（同一弹丸的次级振动不重复触发）。
- **持续判定**：差分信号超阈值连续样本数 ≥4（1.02ms）才判有效，排除窄脉冲干扰（原"32 样本环形缓冲求差分峰值"的窗口峰值判据已随两段式判定移除，`win_len` P02 字段当前无消费者）。
- **锁帧口径**：冻结缓冲保留**未差分的 hp/hit_sum**（原始力学信号）——动量/位置等高级算法（7.8）需要的是力学波形而非差分信号；差分仅用于触发判定。触发瞬间快照预触发段，之后每帧补入；窗口满（P21+P22）后置确认就绪标志，**同帧**即完成判定，无额外时延。
- **参考样本：训练与载入**（`App/bsp/ref_store.c`，Flash 末页 2KB，见 12 章风险）

  | 时机 | 行为 |
  | --- | --- |
  | 上电 `HitDetect_Init` | `RefStore_Load()`：校验末页（magic+CRC32）→ 拷到 RAM → **立即擦页**（~25ms 阻塞）。有旧值即 `s_ref_valid=1`，去均值固化参考 |
  | 热身期（上电后 5τ，≈10.5s） | **不判拒、不训练**：基线 EMA 从 0 起步，前几个 τ 是对数建立瞬态，此窗内固化参考即污染样本。故击打照常触发/计数/上报，但既不用参考拒判（免得用不纯的窗否掉真实击打），也不固化参考 |

  > 计数口径：`HitDetect_Feed` 每消费一个样本累加 `s_boot_samples`（自检喂帧、REFRACTORY
  > 期间同样计入——EMA 收敛只与样本数有关，与击打状态机无关）。

  > **掉电安全**：页内始终以"有效内容或全 0xFF"结束。擦除与编程之间掉电 ⟹ 页为空 ⟹
  > 下次上电走首次训练路径（后果 = 再紫闪一次）。每上电 ≤1 擦 + ≤1 写，寿命无忧。
  > 擦除只在 `App_Init`（TIM2 启动前）执行，运行期只做纯编程，**ISR 内绝不碰 Flash**。
  > 阻塞期间 DRDY/DMA 照常推进，主循环按 `drop_cnt` 自恢复。

- **确认判据（区分"本体震荡"与"真实击打"）**——在触发后完整窗口上计算，纯整数：

  - `peak` 为**冻结窗 \|dif_sum\| 峰值**（旧值是其子集，无信息损失）。

- **冻结异常**：缓冲溢出等异常路径直接退 REFRACTORY（`s_conf_abort_cnt++`），**绝不停在 CONFIRMING**；它既不是真击打也不是相关度不足，故不产生事件也不产生拒绝记录。

### 7.2 强度量化（"力度/伤害"上报）

- 事件能量：**冻结窗（P21+P22=128 样本）内 Σ|hp|**（可复现、对滤波衰减不敏感）——已在确认段实装为 `impulse`（0.01N·ms，`K_N·Δt·Σ|hp|`，见 7.8）。**窗口取上限后 Σ|hp| 会覆盖更长的衰减尾，`impulse` 数值随之增大**：`peak_ch[4] → force_01n → intensity` 取的是窗内峰值，不受窗长影响；但 `impulse` 的标定口径需按新窗长复核。
- **力度映射（合力模型）**：`F = K_N × Σ(peak_ch[i] × K_ch[i])`——中心对称布局下四通道分力之和与击打位置无关，力度用合力标定与上报；K_N 由 19N/100N 两点砝码标定（见 7.7），单位 0.01N；K_ch 为通道一致性归一化（P07）。
- 强度百分数：`I = clamp((F − 19N)/(490N − 19N), 0, 100)`（%），`peak_ch[4]` 一并上报，供核心板二次处理与位置反推。

### 7.3 击打事件数据结构

```c
typedef struct {
    uint8_t  ch;          /* 触发通道（合力信号判定时恒为 0xFF=融合，预留） */
    uint8_t  intensity;   /* 强度 0-100%（合力模型，7.2） */
    uint16_t force_01n;   /* 合力，0.01N 单位（7.2） */
    uint32_t peak;        /* 冻结窗 |dif_sum| 峰值 */
    uint32_t peak_ch[4];  /* 冻结窗各通道 |hp| 峰值分布（反映击打位置，供 7.8 位置估算） */
    uint32_t ts_ms;       /* 触发时刻（HAL_GetTick）：确认通过后仍沿用触发时刻，非上报时刻 */
    uint32_t impulse;     /* 冲量 0.01N·ms = K_N·Δt·Σ|hp|（K_N=0 未标定时为 0，7.8） */
    uint16_t duration_ms; /* 撞击时间=半高脉宽（|hp_sum|≥峰值/2 的样本数×0.256ms） */
} hit_event_t;
```

### 7.6 自检流程（上电 + CAN 命令可触发）

1. 驱动层自检：ID/全部寄存器回读（6.3）、DRDY 翻转、NULL 帧响应。
2. 采集 100ms 统计：各通道均值（基线）、RMS 方差；1 < 方差 < 50 counts 且基线在标定窗内 → 通过。（**2026-09-09 注**：PGA 设为 8× 后该门限维持不变——用户判定噪声主要来自 ADC 本身，PGA 不放大其 counts；若量产板实测 RMS 超 50 需重议门限。）
3. TEMP 4 路在窗内（P11）且未超温（P19）。
4. **DAC 注入（可选，参数开关）**：PA4（DAC1_OUT1）输出 1.65V±0.5V 阶跃，验证注入通道响应；亦为极性校对（6.7）的注入源。
5. 结果经 USART1 调试日志输出（自检本身不置故障位）；失败时通信链路保持可用以便诊断。

> **实现状态（2026-09-09）**：1~3、5 步已落地为**非阻塞状态机** `App/app/self_test.c`（主循环每圈步进，单步 <1ms，总时长 ≈1.1s、超时 5s abort）：寄存器回读校验（ID/MODE/CLOCK，含 REVID=0x05 只读策略）→ 1s DRDY 频率（3906±20%）→ 256 帧均值/RMS（|mean|≤25%FS 且 1≤RMS≤50，300ms 无帧提前失败）→ TEMP 窗检。运行期间自检独占帧消费并持续喂 HitDetect（管线不停摆）。上电自动发起（**ADC 初始化失败时不发起**）；无 CAN 命令触发通路（原 0x51 触发随 ISO-TP 移除而作废）；PVD sticky 存在时 FAULT 态每 5s 自动重试。**通过 → 清除 sticky 故障（POWER/SPI）**；结果经 USART1 日志输出（`[SELFTEST] PASS drdy=…` / `[SELFTEST] FAIL bits=0xNN …`），TLV/STATUS_REPORT 型上报未实现。第 4 步 DAC 注入仍为可选扩展（不在当前实现）。

### 7.7 标定方法（M2 阶段）

- **力度两点标定（合力标定）**：19N 与 100N 砝码静压于击打平面，记录对应**合力峰值**（Σ peak_ch）→ 线性拟合 K_N；**加载点不限中心**——中心对称布局下四通道分力之和与加载位置无关。
- **通道一致性**：同一砝码逐通道加载 → K_ch[4] 归一化。
- **极性校对**：一次已知方向击打（或 DAC 注入已知符号），校验各通道响应符号 → 写入符号掩码（6.7）。
- **阈值整定**：采集 CSV 离线分析噪声分布与击打波形，THR_HIT 取"19N 标定值×1.2"或按 6σ 噪声准则取大者。
- 标定结果写入 Flash（双槽 + CRC，`calibration.c`）。

> **Flash 分区（重要，2026-10-16）**：末页 `0x0801F800`（STM32L432KB=128KB，2KB/页，页号
> 63）已被**击打参考样本**占用（`App/bsp/ref_store.c`）；应用镜像当前 ≈50KB，与末页相距
> ≈78KB。后续 `Cal_Save`/ID 持久化等**不得占用末页**，从倒数第二页往低地址排。

### 7.8 弹速与入射角反推（预留扩展，M6）

比赛仅一种弹丸，**不做弹丸类型分类**；弹丸质量以宏定义（值待确认，官方 17mm 弹丸约 3.2g）：

```c
#define PROJECTILE_MASS_0P1G  (32)   /* 弹丸质量，0.1g 单位，值待确认 */
```

预留"动量-撞击时间联合反推弹速与入射角"接口（`HitDetect_EstimateImpact()`，见 5.3），设计要点：

- **波形捕获**：击打触发时冻结 K 帧环形缓冲的窗口——预触发 P21 深度（默认 16.4ms 历史，覆盖冲击上升沿）+ 触发后 P22 窗口（默认 16.4ms 衰减段）→ `HitDetect_GetWaveform()` 输出完整冲击波形。（**已实装**，且同一冻结窗被确认段复用，见 7.1。）
- **撞击时间（脉宽）**：**已实装**——取半高脉宽（`|hp_sum| ≥ 峰值/2` 的连续样本数 × Δt 0.256ms）→ `duration_ms`。
- **动量（冲量）**：**已实装**——`impulse = K_N·Δt·Σ|hp(n)|`（K_N 来自 7.7 力度标定，Σ 取冻结窗全程），单位 **0.01N·ms**；K_N=0（未标定）时为 0。
- **弹速估算（预留公式）**：`v ≈ Impulse / (PROJECTILE_MASS × (1+e))`，e 为恢复系数（弹丸碰撞性质修正），待 M6 实弹标定。
- **入射角估算（预留思路）**：应变桥主要测法向力——用法向冲量分量与总冲量之比结合撞击时间随角度的变化关系建模，待 M6 实弹标定。
- **击打位置估算（预留）**：四传感器中心对称分布 → 由四通道峰值分布反推击打位置：`x ∝ ((P2+P3) − (P1+P4)) / ΣP`、`y ∝ ((P1+P2) − (P3+P4)) / ΣP`（P1~P4 为 peak_ch[4]，坐标轴定义按实际布局在 M2 确定）；预留接口 `HitDetect_EstimatePosition()`，上报帧预留位置字段（协议方确认后启用），与弹速/入射角一同在 M6 标定落地。
- **采样率带宽说明**：3.9kSPS 下 sinc3 带宽 ≈0.26×fDATA≈1kHz，对 1~5ms 冲击脉冲基本足够；若分辨率不足，P20 OSR 降 256 → 15.6kSPS。
- **上报扩展预留**：HIT_EVENT 新增 impulse/duration 字段（协议方确认后启用，见 `Docs/CAN_PROTOCOL.md`）。

## 8. 灯驱动设计

### 8.1 WS2812 驱动方案：USART2 3.75MBd + TX 反相 + DMA（2026-08-21 定稿）

**方案移植自已验证的发射机构工程**（SHOOT_cmzy_REV081/Core/Src/ws2812_uart.c，同款 GL5050 灯带）：

- **USART2 @ 3.75MBd（位宽 ≈267ns）+ TX 反相（TXINV）**：反相后空闲 = 低电平 = WS 复位码，帧间无需显式复位字节（帧间隔 50ms ≫ 50µs 自然锁存）。CubeMX：Baud=3750000、OverSampling=8、Advanced Features → **TX Pin Active Level Inverted**（曾因 CubeMX 未勾选该选项导致全白——生成代码的 AdvancedInit 赋值会覆盖 USER CODE 手动设置，最终以 CubeMX 配置定稿）。
- **编码**：每 WS 位 4 个 UART 位（'0'=[0,0,0,1]、'1'=[0,1,1,1] 线电平），每字节 2 个 WS 位；编码表 `{0xEF, 0x8F, 0xEC, 0x8C}`；每灯 24bit **GRB 序** MSB 先行 → 12 字节/灯。
- 自研的 2.667MBd 分数格方案（3 WS 位/字节）实测混色乱序，弃用（记录在案）。
- TX DMA（DMA1_Ch7）：156B@3.75MBd ≈ 416µs 后台传输，DMA 必要性分析结论不变（阻塞式可用、中断式不可行、DMA 推荐）。

WS2812 时序要求：24bit@800kHz，0 码 0.35µs 高/0.9µs 低，1 码 0.9µs 高/0.35µs 低，周期 1.25µs±0.6µs，复位 ≥50µs。

- **灯数上限 13 颗**：板载 1 颗（第 1 颗）+ 左侧装甲板 6 颗 + 右侧装甲板 6 颗，**串联顺序：板载 → 左 6 → 右 6**。帧缓冲 `led_frame[13×12] = 156B`，一次 DMA ≈ 416µs。
- **帧刷新 20Hz**（50ms 节拍，与 TIM2 1kHz 分频对齐）：动画相位在 TIM2 1kHz 中断推进，**每个 50ms 网格无条件重建帧并启动 DMA 发送**（DMA 忙时跳过本次，见 `led_status.c`）；5Hz/1Hz 闪烁的半周期（100ms/500ms）均为 50ms 网格的整数倍，无量化失真。
- PA2 GPIO：**推挽 + Very High**（覆盖 CubeMX 半双工生成的开漏+上拉，风险 R8）。
- 亮度：全局亮度参数（P15），写入前 RGB 各通道 `v×B/100` 缩放；动画（快闪/慢闪/交替）在模式生成时按相位调幅（相位由 TIM2 1kHz 中断推进）。

不变）。相位用 `s_train_ms`（自 BOOT 的墙钟）判断而非 `s_state_ms`，这样 HIT/ID 态打断 REF_PENDING
再拉回时进度不丢；相位翻转只在 `Sm_RefPhaseTick()` 内发生，且**只在相位变化点**调 `LedStatus_SetEffect`。
注：紫 1Hz 慢闪与 ID_SETUP 的队色慢闪节奏相同、紫 5Hz 快闪与 HIT 的队色快闪节奏相同，**靠颜色区分**。

| 故障类别 | 故障位 | 图案 | 颜色 A | 颜色 B/灭 |
| --- | --- | --- | --- | --- |
| 传感器读取值 | bit0-11 | 官方红蓝 500ms 交替（不变） | 粉 255,50,100 | 湖蓝 0,180,255 |

## 9. 通信集成设计（固定帧 CAN 协议）

> **当前实现（2026-09-06）**：本工程已移除 ISO-TP、应用帧、TLV、ACK 调度器与 CAN 心跳，改为**标准 11-bit 固定 CAN 帧**：枚举 `0x120~0x123` + 业务帧 `0x130+(NodeID-1)×0x10+offset`（Node1=`0x130~0x139`……Node4=`0x160~0x169`），收帧滤波 `0x100~0x17F`（标准数据帧）。唯一有效的协议定义为 [`CAN_PROTOCOL.md`](CAN_PROTOCOL.md)；本章下方原有 9.1~9.4 内容仅保留为历史设计记录，不得用于联调或生成报文。

### 9.1 协议栈结构（已调研确认）

- 传输层 `transport/isotp.c`：ISO-15765-2 标准 PCI 分帧（单帧/首帧/连续帧/流控），512B 收发缓冲，无扩展寻址、无 CRC（应用层也无 CRC，见协议 v2 说明）。
- 应用帧 `protocol/app_frame.c`：8 字节头 = dst_id、src_id、module_uid(2B LE)、func_code、seq（0=不需 ACK）、data_type、data_len + TLV 数据。
- 服务层 `service/`：按 func_code 分发（dispatcher）+ 发送队列/ACK 重试（retry_ack_scheduler，单窗口、8 条队列）。**调度器非 ISR 安全**：协议入队一律在主循环上下文执行，TIM2 中断只置标志。
- 轮询式设计（无 RTOS）：主循环调用 `Transport_Isotp_Poll()` + `Service_RetryAckScheduler_Poll()`；CAN 收经 FIFO0 中断回调。

### 9.2 移植步骤清单

1. 拷贝栈文件至 `App/comm/`（5.2 清单），transport/protocol/service **零修改**。
2. **重写 `app_can.c`**（L432 绑定）：`App_Can_GetHandle` 仅返回 `&hcan1`；滤波器 bank0 IDMASK 全接收（协议为应用层路由）；`App_Can_Init` = **NART=1（禁自动重传，死总线阻塞根治，2026-09-05 实测）** + `HAL_CAN_Start` + `HAL_CAN_ActivateNotification(RX_FIFO0|EW|EP|BOFF|LEC)`；TX 保持"等邮箱→预清完成标志→AddTxMessage→等 RQCP（硬限 5ms）→**TXOK 判真实成败**"逻辑；回调桥接 `HAL_CAN_RxFifo0MsgPendingCallback → App_Can_DispatchRx`（FIFO0 排空式）；`HAL_CAN_ErrorCallback` 记日志 + Bus-Off 后**寄存器级非阻塞恢复**（ISR 置标志，主循环 INRQ→INAK→清 INRQ 三步状态机，无 Stop/Start 阻塞）。
3. `app_log.c` 可选：USART1 115200 阻塞打印（DEBUG 开关）。
4. 实例化：`TransportIsotpContext g_isotp`（tx_id/rx_id 见 9.3，st_min_ms=10、tx_timeout=100ms、get_ms=HAL_GetTick）+ `ServiceRetryAckScheduler g_sched`。
5. 接线：`App_Can_SetRxCallback(→ Transport_Isotp_OnCanFrame)`；RX 应用帧 → `Protocol_AppFrame_Decode` → `Service_Dispatcher_DispatchRaw`；ACK 匹配 → `Service_RetryAckScheduler_OnReceivedFrame`。
6. 主循环每圈调用两个 Poll 函数。

### 9.3 CAN 层 ID 分配（**建议值，需与核心板确认**，风险 R15）

- 本板发送 ID：**0x1A0**（ISO-TP 单帧/多帧同 ID）；接收 ID：**0x2A0**；预留 0x1A1~0x1AF 给多装甲板扩展（按 armor_id 偏移）。
- 500kbps：presc=10、BS1=13、BS2=2、SJW=1、16TQ/bit、采样点 87.5%。
- 应用层地址：src_id=0x0A（装甲板，建议值）、dst_id=0x01（核心板）；module_uid=MCU UID 低 2 字节。

### 9.4 本板消息集

**上行（本板 → 核心板）**：


| 功能码 | 消息              | 数据类型                                                                     | 周期/触发                                                             | seq/ACK                   |
| -------- | ------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------- | --------------------------- |
| 0x01   | MSG_HEARTBEAT     | U32（ms 时间戳）                                                             | **50ms（20Hz**，TIM2 节拍置标志，主循环入队）                         | 0                         |
| 0x02   | MSG_STATUS_REPORT | TLV_STREAM：TLV_STATE(0x03) + TLV_VALUE(0x05, 故障位图 u16，位布局见 7.5 统一表) + TLV_TEXT(0x06, 自检结果) | 状态变化沿即时上报（**≥100ms 节流**，HIT/ID 闪灯态不即报）+ 周期上报（**默认 1Hz，可调 P24**） | 0                         |
| 0x31   | MSG_HIT_EVENT     | TLV_STREAM：通道(u8)+强度(u8)+力度(u16,0.1N)+时间戳(u32,ms)+峰值(u32)        | 有效击打，受 50ms 不应期约束                                          | 0（事件唯一性，禁止重试） |

**下行（核心板 → 本板）**：复用 0x51 MSG_LAUNCHER_CTRL_CMD 的 TLV_CMD_INDEX + TLV_PAYLOAD 机制（**复用该功能码与新 TLV 类型码均需协议维护者确认并同步《通信协议v2》**，风险 R15）：


| CMD_INDEX | 含义     | Payload TLV                                                                     | 应答                      |
| ----------- | ---------- | --------------------------------------------------------------------------------- | --------------------------- |
| 0x01      | LED 控制 | TLV_EFFECT（0=队色/1=灭/2=呼吸/3=自定义）+ TLV_VALUE(0xRRGGBB) + TLV_BRIGHTNESS | ACK                       |
| 0x02      | 参数配置 | TLV_PARAM_ID(u16) + TLV_PARAM_VALUE(u32)（写后回读校验）                        | ACK                       |
| 0x03      | 参数读取 | TLV_PARAM_ID                                                                    | 0x51 回帧 TLV_PARAM_VALUE |
| 0x04      | ID 设置  | TLV_ARMOR_ID(u8)，写入 Flash 双槽+CRC                                           | ACK（冲突→拒绝结果码）   |
| 0x05      | 自检触发 | 空                                                                              | STATUS_REPORT             |
| 0x06      | 零偏标定 | 空（当前基线固化入 Flash）                                                      | ACK                       |

新 TLV 类型码建议值（占用协议预留区，需同步更新协议文档）：0x30=HIT_CHANNEL、0x31=HIT_INTENSITY、0x32=HIT_FORCE、0x33=HIT_TS、0x34=HIT_PEAK、0x35=FAULT_FLAGS、0x36=TEMP(0.01V)、0x37=BRIGHTNESS、0x38=EFFECT、0x39=PARAM_ID、0x3A=PARAM_VALUE、0x3B=ARMOR_ID。

- 下行命令（seq≠0）→ 回复 MSG_ACK（0x06，复制 seq + TLV_ACK_FUNC），经调度器重试（3 次 × 200ms）。
- **掉线判定**：**200ms（默认 4 个心跳周期）**未收到核心板心跳 → COMM_LOST（心跳照发、状态上报）；恢复即回 NORMAL。心跳 20Hz 增加的 CAN 负载（ISOTP 单帧 8B@50ms）对 500kbps 总线可忽略（<0.3% 带宽）。

## 10. 任务调度（TIM2 定时中断 + 主循环）

### 10.1 设计原则

**状态维护与刷新不放在主循环阻塞跑**：开 **TIM2 1kHz 中断**以固定周期执行状态机、灯动画与健康评估节拍；主循环只承担帧消费、检测管线与通信主循环。TIM2 ISR 内只做纯计算与置标志；CAN 收帧 ISR 只置标志/复制小帧入队，**所有发送、应答与重试统一在主循环 `BoardComm_Loop()` 内完成**（每圈最多一帧 CAN）。

### 10.2 TIM2 1kHz 中断任务表（`App_OnTick1ms()`）


| 任务           | 分频 | 周期             | 说明                                                                                                                |
| ---------------- | ------ | ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 状态机步进     | 1    | 1ms（1kHz）      | 状态转移判定与灯模式切换（第 11 章，保持不变）                                                                      |
| LED 动画相位   | 1    | 1ms（1kHz）      | 快闪 5Hz/慢闪 1Hz/交替相位推进；**帧刷新输出 20Hz**（每 50ms 网格重建帧并启动 DMA，DMA 忙则跳过，见 8.1）           |
| 传感器健康评估 | 50   | **50ms（20Hz）** | 饱和/偏置/方差/DRDY 超时/超温（7.5）+ TEMP 窗检（ADC1 由**TIM1 CC1 硬件触发**采集 ≈1.22kHz，本任务取最近转换结果） |

### 10.4 CPU 占用估算（80MHz）

SPI 方案 A 的 ISR 开销 ~0.8%（2µs×3.9k）+ 检测管线 ~1.2%（3µs×3.9k）+ TIM2 ISR ~1% + CAN ISR ~0.3% + 杂项 ~0.5% ≈ **总计 4~5%**，裕量充足。实测以 `s_iter_us`（最近一次 App_Loop 迭代耗时）与 `s_loop_max_us`（1s 窗口内最大迭代耗时）为准。

**时基**：1ms 用 TIM2 中断（状态/灯/健康节拍）；HAL_GetTick（SysTick）供通信层超时/掉线计时（`s_last_l431_rx_ms`）；**CAN 击打事件帧不含时间戳**，载荷为 seq/ch/intensity/force/peak 低 24bit（`ts_ms` 仅留在结构体内供调试）。

**RAM 预算（64KB）**：实测 `data 144B + bss 17456B` ≈ **17.2KB（27%）**（`arm-none-eabi-size` 于当前构建）。主要占用：**ADS131M04 初始化帧缓冲 2304B**、**环形帧缓冲 576B（K=32×18B）**、参考样本 512B（128×int32）、ref_store 页缓冲 528B、**WS2812 帧缓冲 156B**。栈 1KB（.ioc StackSize=0x400）。

## 11. 状态机设计

状态维护由 **TIM2 1kHz 中断每 1ms 步进**（不阻塞主循环），转移条件基于击打事件、故障位、链路超时与电管请求。

**门控优先级（`StateMachine_Tick` 的判定顺序，2026-10-16 定）**：
`各类模块故障 > 紫闪校准（REF_PENDING）> 装甲模块离线（COMM_LOST）> 队伍色/ID/受击`。
即：紫闪期间出故障立刻转 FAULT（故障图案优先）；离线时若仍在校准窗口仍显示紫闪
（校准是上电暂态，先完成再显示离线）。`REF_PENDING` 也接受击打事件（`OnHitEvent` 的
状态白名单含它）——上电后第一击正是训练击打，若在此被忽略，main_app 的
`Get()==HIT` 上报门会把这一击吞掉。

**REF_PENDING 的紫闪分两段（2026-10-17）**：① 热身段——自 BOOT 起 5τ（`HitDetect_GetWarmupMs()`，
s_bl=13 → ≈10.5s）内**紫 1Hz 慢闪**，此间检测层不判拒、不训练；② 探测段——热身结束后 20s
**紫 5Hz 快闪**（旧灯效语义不变）。相位由 `Sm_RefPhaseTick()` 按 `s_train_ms` 判定并只在相位
变化点刷灯；翻转必须由顶层校准门路径驱动——门每 tick 调用 `Sm_ToRefPending()` 后提前 return，
`case SM_STATE_REF_PENDING` 只在门放行后才可达，把翻转放在 case 里永不执行。

```
  BOOT ──白灯300ms──▶ REF_PENDING ──已训练/热身+20s超时沿用旧值──▶ NORMAL
  （上电未训练参考时经紫闪校准：紫 1Hz 慢闪热身 5τ≈10.5s → 紫 5Hz 快闪 20s 探测窗；
    NORMAL 是最初状态，无参考且超时则一直留在紫闪）
                      NORMAL ──有效击打──▶ HIT ──300ms──▶ NORMAL
    │                 │ ▲                        │
    │ 自检失败         │ │ 请求恢复               │
    ▼                 │ │          ┌─300ms 无请求┐ │
  FAULT ◀──故障闩存───┘ │          ▼             │ │
    │  ▲  └─自检OK─────┘        COMM_LOST       │ │
    │  │                          │ 请求恢复      │ │
    │  │       ID_SETUP ◀──0x51 ID_SET──┐        │ │
    │  │        │ │设置完成/取消         │        │ │
    │  │        │ ▼                     │        │ │
    │  │        ID_CONFLICT ◀──主控ACK拒绝─┘       │ │
    └──重启/清错────────────────────────────────────┘
```

> 图中 ID_SETUP/ID_CONFLICT 支路（`0x51 ID_SET`、主控 ACK 拒绝）为**预留示意**：`StateMachine_OnIdSet()` 当前无调用者、两态不可达，进入后 1s 显示完自动回 NORMAL。


| 状态        | 进入条件                                   | 灯光（见 8.2）                      | 协议联动                                                  |
| ------------- | -------------------------------------------- | ------------------------------------- | ----------------------------------------------------------- |
| BOOT        | 上电                                       | 白 300ms                            | -                                                         |
| REF_PENDING | BOOT 结束且**本次上电尚未训练参考**，且（**热身 5τ + 20s** 探测窗未过 **或** Flash 无旧值） | **紫 1Hz 慢闪（热身段）→ 紫 5Hz 快闪（探测段）**，PB1 灭（区别于紫常亮=离线） | 无上报；退出条件见下 |
| NORMAL      | 自检通过 / 校准结束                        | 队色常亮，**PB1 亮**                | 无周期上报；状态由电管查询被动回复（业务槽偏移 0x4/0x5）  |
| HIT         | **触发**（\|hit_dif\|≥THR_HIT 且持续≥P03）**且确认通过**（P27 相关判据未拒绝，7.1） | 队色快闪，**PB1 亮**                | 发击打事件帧（业务槽偏移 0x3，递增 sequence，每 100ms 重试至 ACK）；FAULT/COMM_LOST 态不发送只计数。被拒触发**不进入本状态**、不产生事件 |
| FAULT       | 任一故障位（Fault_GetBitmap）闩存        | 分类图案表（8.2），PB1 灭；**超温时 PB0 亮** | 故障位图帧（业务槽偏移 0x1，变化沿即发/非零每 100ms 重发）；PVD sticky 时每 5s 自动重试自检 |
| COMM_LOST   | **300ms** 未收到正确寻址到本板槽位的电管请求（`BOARD_COMM_LOST_MS`） | 紫常亮，PB1 灭                      | 无上报；收到任一合法本板请求即回 NORMAL                    |
| ID_SETUP    | **（预留，当前无进入路径）**原 0x51 ID_SET | 慢闪，**PB1 亮**                    | 预留：1s 显示后自动回 NORMAL（`StateMachine_OnIdSet` 无调用者） |
| ID_CONFLICT | **（预留，当前无进入路径）**主控 ACK 拒绝（重复 ID/UID） | 红蓝紫循环，PB1 灭                  | 预留：1s 显示后自动回 NORMAL                              |

> **REF_PENDING 退出条件**（每 1ms 评估）。**退出时统一由 `Sm_LeaveRefPending()` 收尾**：本次
> 上电未训练就把 RAM 里的旧参考回写 Flash（本上电开头 `RefStore_Load` 已**无条件擦页**，不回写
> 就等于清空跨断电参考）。三条路径：
>
> ① **上位机上线**（2026-10-17 新增，`BoardComm_MasterHeard()`）**且 Flash 有旧值** → 立即回
>    NORMAL——整车已在工作，不该再等热身/探测窗。该标志只认"电管→装甲板"方向的报文
>    （枚举 `0x120`/`0x122` + 本板槽位的查询/LED 控制/ID 查询/击打 ACK），兄弟板的 `0x121`/`0x123`
>    与本板上报帧都不算。**BOOT 阶段被打断也走这条**：300ms 白灯走完直接进 NORMAL，全程不闪紫。
> ② 本次上电**热身后**第一次击打被接受 → 已训练 → 回 NORMAL。
> ③ 热身结束起满 20s（`REF_TRAIN_TIMEOUT_MS`，自 BOOT 起 ≈30.5s）**且 Flash 有旧值** → 回 NORMAL。
>
> **Flash 空时（`HitDetect_RefValid()=0`）①③ 的"沿用旧值"分支都不成立 → 保持紫闪走正常校准，
> 直到第一次击打**（无参考可继承，必须训一个出来）。已知风险：探测窗内整车振动若触发并
> **被接受**，会污染参考——用户已明确接受；缓解手段是窗口限时 + 下电重训；**热身 5τ 内训练
> 已禁用**（见 7.1），该段基线 EMA 的建立瞬态不再有污染风险，热身期击打照常计数上报但不判拒、
> 不训练。
