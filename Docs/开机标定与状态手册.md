# 装甲模块开机标定与状态手册

版本：v1.0（2026-10-17）
适用固件：`Armor_Cmzy26_081`，分支 `Test_RegularEdition_082`（量产版/常规版）

本文写给**上电台架的操作者与联调人员**，回答四个问题：

1. 上电之后这块板在干什么、还要多久、什么时候能开打；
2. 参考样本存在 Flash 的什么地方、什么时候被擦、什么时候被写、掉电会不会丢；
3. 上位机（电管）如果已经在线，怎么跳过等待；
4. 灯在闪什么、同一个紫色为什么有两种含义、PB0/PB1 什么时候亮。

> **代码是唯一权威。** 本文所有数值都可在源码中逐一对上，标注了出处。参数的具体数值（尤其是 P27）默认值只在 `App/detect/calibration.c` 的 `Cal_GetDefaults()` 一处定义，**本文不复述这些数字**。

## 0. 三十秒速览

| 板上没有电管、Flash 里也没有参考（全新板） | 板上没有电管、Flash 里有参考 | 电管在线、Flash 里有参考 |
|---|---|---|
| 白 300ms → 紫 1Hz（≈10.5s）→ 紫 5Hz（20s）→ **之后一直紫 5Hz**，直到有人真正敲一下 | 白 300ms → 紫 1Hz（≈10.5s）→ 紫 5Hz（20s）→ 紫常亮（离线） | 白 300ms → **直接队色常亮**，不进校准 |

三条结论：

- **只有「训练成功」能让全新板离开紫闪**。Flash 空的时候，等多久都不算完，必须打一记真击打。
- **参考页只在训练写入时擦+写**（每上电至多一次）；任何非写入时刻掉电都不丢参考（见 §3.4）。
- **紫 1Hz 慢闪 / 紫 5Hz 快闪 / 紫常亮是三种不同状态**，前两者是校准，后者是"电管没在跟我说话"。

## 1. 上电时间轴

### 1.1 总表

以 `StateMachine_Init()` 返回、TIM2 1kHz 开始打拍为 `t = 0`（`App/app/main_app.c:98`，`HAL_TIM_Base_Start_IT(&htim2)` 是 `App_Init` 的最后一行）。所有时长以此为基准。

| 阶段 | 起点 | 时长 | 灯 | 板子在做什么 |
|---|---|---|---|---|
| **BOOT** | t=0 | **300 ms** 固定（`SM_BOOT_MS`，`state_machine.c:35`） | 白色常亮 | 自检步进、确认 `Fault_GetBitmap()` 干净；此阶段**不理会**校准门 |
| **REF_WARMUP** | t=300ms | 到 **t≈10485 ms**（`HitDetect_GetWarmupMs()`，取决于 P01 `s_bl`） | 紫 **(128,0,128)** 1 Hz 慢闪：500ms 亮 / 500ms 灭 | 基线 EMA 从 0 建立中。击打**照常计数、照常上报**，但**不判拒、不训练** |
| **REF_PENDING** | t≈10485 ms | **20 s**（`REF_TRAIN_TIMEOUT_MS`，`state_machine.c:37`） | 紫 5 Hz 快闪：100ms 亮 / 100ms 灭 | 击打探测窗。此窗内**第一记被接受的击打**会被固化为参考并写 Flash |
| **退出** | 三条路径任一条命中（§2） | — | 队色常亮（NORMAL）或紫常亮（COMM_LOST，见 §6） | 进入正常业务 |

**超时点的两种算法**（两者都要满足才算"窗口关死"）：

- 灯效侧用**墙钟**：`s_train_ms >= s_warmup_ms + REF_TRAIN_TIMEOUT_MS`，即 `10485 + 20000 = 30485 ms ≈ 30.5 s`；
- 判据侧用**样本数**：`s_boot_samples >= 5 × 2^s_bl = 40960 样本`（`hit_detect.c:524`）。

正常运行时两者一致（40960 样本 ÷ 3.90625 kHz = 10.486 s；`GetWarmupMs()` 取整成 10485 ms）。**只有丢帧时样本数会滞后**，此时"紫灯已经转快闪"比"判据真正生效"略早几个毫秒。这是有意为之的取舍——灯是给人看的，判据要严格。

### 1.2 时序图

```
t=0          300ms                     ≈10.5s               ≈30.5s
 │             │                          │                    │
 ├── 白常亮 ───┼──── 紫 1Hz 慢闪 ─────────┼── 紫 5Hz 快闪 ─────┼──→ 退出
 │   BOOT      │      REF_WARMUP          │   REF_PENDING      │
 │             │                          │                    │
 │  自检+故障  │   EMA 沉降，样本不纯      │  第一记被接受      │  有旧参考→队色常亮
 │             │   不判拒、不训练          │  的击打 → 训练     │  无旧参考→继续紫 5Hz
```

### 1.3 热身时长怎么算出来的

| 量 | 公式 | s_bl=13（默认）时 |
|---|---|---|
| EMA 时间常数 τ | `2^s_bl` 样本 | 8192 样本 = **2.097 s** |
| 热身窗口 | `5 × 2^s_bl` 样本（`Hit_WarmupRecompute()`，`hit_detect.c:288`） | 40960 样本 = **10.486 s** |
| 对外毫秒数 | `samples × 256µs ÷ 1000`（`HitDetect_GetWarmupMs()`） | **10485 ms** |

- 1 样本 = 1/3.90625 kHz = **256 µs**。
- `s_bl` 被 `Hit_ClampParams()` 钳在 **1..24**（`hit_detect.c:282`）——`diff >> s_bl` 与 `5u << s_bl` 在移位数 ≥32 时是未定义行为，所以哪怕 P01 被写坏也不会跑飞。改动 P01 会同时改变热身时长与灯效相位翻转点。
- `s_warmup_ms` 在 `StateMachine_Init()` 里向检测层取一次后**缓存**，此后不再变（`state_machine.c:119`）。运行期改 P01 不影响本次上电的灯效节奏。

## 2. 三条退出路径

`Sm_RefPendingNeeded()`（`state_machine.c:59`）每 1 ms 评估一次。返回 0 = 放行、返回 1 = 继续紫闪。

```c
if (HitDetect_RefTrainedThisBoot())                    return 0;   /* ① 已训练 */
if (BoardComm_MasterHeard() && HitDetect_RefValid())   return 0;   /* ② 上位机在线 + Flash 有旧值 */
if (s_train_ms < s_warmup_ms + REF_TRAIN_TIMEOUT_MS)   return 1;   /* 窗口未关死 → 继续等 */
return HitDetect_RefValid() ? 0 : 1;                               /* ③ 超时 + 有旧值 */
```

| # | 路径 | 触发条件 | 语义 |
|---|---|---|---|
| ① | **训练完成** | 热身后第一记**被接受**的击打 | 这是唯一能在 Flash 为空时脱困的路径 |
| ② | **上位机在线** | 收到过任意"电管→装甲板"方向的帧 **且** Flash 有可用参考 | 整车已经在跑，不该为了等热身耽误它（详见 §4） |
| ③ | **超时沿用** | 热身 5τ + 20 s 到点 **且** Flash 有可用参考 | 台上没人敲，就用上次的参考继续打 |

**关键约束**：② 和 ③ 都带 `HitDetect_RefValid()` 条件。**Flash 空时这两条路都不成立**，板子会一直停在紫 5Hz 快闪——没有旧值可以继承，必须真打一记把它训出来。

> 如果台上遇到"紫 5Hz 闪了十分钟还不走"，先看串口有没有 `[CONF] trained`，再看 `HitDetect_RefValid()`。最可能的原因是 Flash 是空的而没人真打。

### 2.1 退出时统一走 `Sm_LeaveRefPending()`

所有退出路径（含 BOOT 阶段被上位机打断的那条）都收口到 `Sm_LeaveRefPending()`（`state_machine.c:73`）：

```c
s_state = SM_STATE_NORMAL;
s_state_ms = 0u;
LedStatus_SetEffect(LED_EFF_NORMAL);
```

**退出无需任何 Flash 写入**（2026-10-17 方案 B）：`RefStore_Load` 上电时**不再擦页**，页里始终保留旧参考（见 §3.2），本上电唯一一次写入是训练击打时的擦+写。所以"未训练即退出"直接沿用页里的旧值即可——参考天然跨断电保留，不存在"忘了回写就清空参考"的路径。

## 3. Flash 参考锁存机制

实现：`App/bsp/ref_store.c` / `.h`。

### 3.1 物理布局

STM32L432KBU6 为 128 KB Flash、2 KB 页、共 64 页（页号 0~63）。**页 63（`0x0801F800`）整页专供参考样本**。

```
0x0801F800 ┌──────────────────────────────────────┐
           │ magic      uint32  0x52454631 'REF1' │  4 B
           │ version    uint16  1                 │  2 B
           │ n          uint16  1..128            │  2 B
           │ sum[128]   int32[] 合力冻结窗（未用部分填 0）│ 512 B
           │ crc32      uint32  覆盖上方 520 B     │  4 B
           │ rsvd       uint32  恒 0              │  4 B
0x0801FFFF └──────────────────────────────────────┘  共 528 B
```

- **单份，无备份槽**。整页 2 KB 只用 528 B，剩余部分保持擦除态。
- `sum[]` 是**未去差分**的合力 `hit_sum` 冻结窗（不是触发用的差分信号）。
- `crc32` 是反射式、多项式 `0xEDB88320`，**逐位软件实现**（1 KB 常量表省掉了），覆盖范围是 `magic` 起到 `sum` 末字节，即 `offsetof(crc) = 520` 字节。
- `_Static_assert` 双保险：页号必须等于 63、结构体必须等于 528 字节。改布局会编译失败。
- 地址是**硬编码**的，不用 `stm32l4xx.h` 的 `FLASH_SIZE` 宏（那个宏要读系统区寄存器，且链接脚本的 256K 是 CubeMX 通用默认值，对本芯片不准）。

### 3.2 上电读流程（`RefStore_Load`）

1. 先查 `magic` / `version` / `n ∈ 1..128` —— 空页读出全 `0xFF`，这一步就判掉了，**不白跑 CRC**；
2. 再算 CRC32 比对；
3. 校验通过 → 拷贝 128 个样本到 RAM，返回 `true`；否则 `*n = 0`，返回 `false`。

**不擦页**（2026-10-17 方案 B）。旧参考一直留在页里，直到本上电训练写入时被覆盖——这是"任何非写入时刻掉电都不丢参考"的根基。`RefStore_Load` 是纯读，无阻塞。

### 3.3 写入时机（`RefStore_Save`）

全工程只有**一个**调用点（2026-10-17 方案 B），在主循环上下文：

| 调用点 | 触发条件 | 位置 |
|---|---|---|
| `Hit_RefTrain()` | 热身结束后**第一记被接受的击打** | `hit_detect.c:265` |

写入是**先擦页再编程**：擦 ~25 ms + 写 ~6 ms ≈ **31 ms**（Flash 只能把 1 写成 0，每次写都须先擦；擦除失败则页保留旧内容，`Save` 返回 -1）。

训练链路的时序值得单独说明（`hit_detect.c:576`）：

```
击打被接受 → 填事件入队 → s_hit_count++ → Hit_RefTrain()
                                              ↓
                              Hit_RefFix()：去均值 + 算平方和 → s_ref_valid=1
                                              ↓
                              s_ref_trained_boot = 1   ← 状态机立即能看到
                                              ↓
                              RefStore_Save()  擦+写 ≈31ms 阻塞
                                              ↓
                              [CONF] trained n=128 flash_err=0
```

- **训练的那一击本身照常上报**（CAN + 串口日志），不会因为被"用来当模板"而被吞掉。
- 31 ms 的擦+写落在**不应期**（P05 `refractory_ms` 默认 50 ms）之内，所以不会错过紧随其后的击打——写入点选在训练处正是为此。
- `s_ref_trained_boot` 在写 Flash **之前**就置位，因此即使 Flash 写失败，板子也会退出紫闪正常开打——只是下次上电还是没参考。

### 3.4 失败模式与退化

| 情形 | 后果 |
|---|---|
| 页为空 / CRC 不符 / 魔数不符 | `RefValid() = false` → 本次上电必须重新训练（紫闪不超时退出） |
| **任意非写入时刻掉电**（上电瞬间、校准期间、正常运行中） | **页完好**——旧参考原样保留，下次上电照常载入 |
| **写入进行中掉电**（训练击打后的 ~31ms 窗口） | 页可能为空或部分写入 → 下次上电走首次训练路径。单页无备份，物理上无法避免 |
| 擦除失败 | `s_ref_err = 1`，`Save` 返回 -1；**页保留旧内容**（擦除失败=内容未动），下次上电仍可载入 |
| 编程失败 | `s_ref_err = 2`，`Save` 返回 -1，参考仍在 RAM 里可用；页可能部分写入 |
| 解锁失败 | `s_ref_err = 3` |

诊断值 `RefStore_GetErr()` 就是 `s_ref_err`（0=无错 / 1=擦除失败 / 2=编程失败 / 3=解锁失败），训练完成时会随 `[CONF] trained n=… flash_err=…` 一起打出来。

**写寿命提醒**：每次上电**至多一次**"擦 + 写"，且仅发生在训练击打时（有旧参考且没人打 = 零写入）。这是单份无备份设计的固有代价，也是为什么**不能用它存高频变化的数据**。将来加 `Cal_Save`、身份信息等持久化时，从**页 62 开始向下生长**，不要挤进页 63。

### 3.5 调用约束（改动前必读）

- `RefStore_Save` **绝不可从 ISR 调用**。它只由训练链路（`Hit_RefTrain`，主循环上下文）调用；擦+写期间 ISR 照常运行，只有主循环停顿。
- 擦除与编程会**停住取指**。方案 B 下两者合并发生在训练击打后的不应期内，主循环阻塞 ~31ms 时 DRDY/DMA 照常推进（按 `drop_cnt` 自恢复）。
- `App/bsp/ref_store.c` 之外**没有任何地方**知道 `0x0801F800` 这个地址。

## 4. 上位机在线跳过机制

目标：整车已经上电在跑的时候，不该为了等一块装甲板热身 30 秒而耽误比赛。

### 4.1 判定"这是上位机发来的帧"

`Bc_IsMasterFrame()`（`board_comm.c:313`）在 **CAN 接收中断**里逐帧判定：

```c
if (id == 0x120 /*ENUM_START*/ || id == 0x122 /*NODE_ASSIGN*/) { return 1; }
return (id == 本板槽位 offset 0x4 /*状态查询*/ ||
        id == 本板槽位 offset 0x6 /*LED 控制*/ ||
        id == 本板槽位 offset 0x8 /*NodeID 身份查询*/ ||
        id == 本板槽位 offset 0xA /*击打事件 ACK*/) ? 1 : 0;
```

命中则置位 `s_master_heard = 1`（**锁存**，本次上电内不会被清掉，只由复位清除）。

**不**算上位机帧的：

- `0x121` / `0x123`（兄弟板的 announce / ACK）——否则兄弟板一说话就会被误判成"电管在线"；
- `0x110`~`0x112`、`0x130`、`0x132`…（本板与兄弟板的上报帧）。

注意前面那个 `if` 在 `CanNode_IsReady()` 判断**之前**执行（`board_comm.c:330`），所以**枚举阶段收到的 `0x120` 就已经能锁存**。而 `CanNode_BusinessId()` 在未 READY 时返回 0，合法帧 ID 恒非 0（收帧滤波为 `0x100~0x17F`），所以不 READY 时后四项自然全部落空，正好只剩枚举帧能命中。

### 4.2 它和"心跳"（COMM_LOST 判据）不是一回事

两个东西用**重叠但不同**的 ID 集合，判据也不同，别混：

| | **上位机在线**（本文档 §4） | **心跳**（掉线判据） |
|---|---|---|
| 变量 | `s_master_heard` | `s_last_l431_rx_ms` |
| 判据 | 只要**方向**对（上位机→装甲板） | 必须**正确寻址到本板槽位** |
| DLC 校验 | 无 | 有（见下） |
| 时效 | **锁存**，一旦置位永不清除 | **滑动超时**，300 ms 无合法请求即判掉线 |
| 用途 | 跳过开机校准 | 进 `COMM_LOST` 状态 |

心跳额外要求 DLC 完全匹配（`board_comm.c:335`）：

- `offset=0x4` 状态查询：`DLC=0`，或 `DLC=8` 且 8 字节全 0；
- `offset=0x6` LED 控制：`DLC=8`；
- `offset=0x8` 身份查询：`DLC=0`；
- `offset=0xA` 击打 ACK：`DLC=1`。

所以**一帧 DLC 不对的 LED 控制命令会点亮"上位机在线"，但不会刷新心跳**。这是刻意的：校准跳过不想因为寻址细节漏判整车已上线，但掉线判定必须严格。

### 4.3 为什么必须"Flash 有旧值"才允许跳过

因为跳过校准意味着**不训练**。如果 Flash 是空的，跳过去就会得到一块"有参考可用"的假象——实际上 `s_ref_valid` 仍然为 0，相关度判据恒为 0，第一记真击打也会被当成噪声。所以条件写成 `BoardComm_MasterHeard() && HitDetect_RefValid()`。

### 4.4 BOOT 阶段被打断

第一条路径（上位机在线 + 有旧值）在 **BOOT 的 300 ms 白灯期间不会被评估**（顶层门写的是 `s_state != SM_STATE_BOOT`，`state_machine.c:145`）。白灯走满 300 ms 后，`case SM_STATE_BOOT` 里调 `Sm_RefPendingNeeded()`，此时返回 0 → 直接 `Sm_LeaveRefPending()` → **队色常亮，全程不闪紫**。

这条路径原本会漏掉 Flash 回写（直接置 NORMAL），现在统一走 `Sm_LeaveRefPending()` 已经补上。

## 5. 灯效完整定义

硬件：13 颗 WS2812（板载 1 + 左 6 + 右 6），USART2 @ 3.75 MBd、**TX 反相**、TX DMA（DMA1_Ch7）。12 字节/颗 → 整帧 **156 B**，一次 DMA **≈416 µs**。**刷新网格固定 20 Hz（50 ms）**，DMA 忙则跳过本次。

除 `ID_CONFLICT`（333 ms 分档）外，**各图案的亮/灭半周期都是 50 ms 的整数倍**（100 / 250 / 500 / 50 与 450），因此 20 Hz 网格上无量化失真。`ID_CONFLICT` 是唯一例外，且它当前不可达（§6）。

### 5.1 灯效枚举（`led_effect_t`，`App/app/led_status.h:20`）

| 值 | 名称 | 图案 |
|---:|---|---|
| 0 | `LED_EFF_NORMAL` | 队色常亮 |
| 1 | `LED_EFF_HIT` | 队色 5 Hz 快闪（200ms 周期：亮 100 / 灭 100） |
| 2 | `LED_EFF_ID_SETUP` | 队色 1 Hz 慢闪（1000ms：亮 500 / 灭 500） |
| 3 | `LED_EFF_FAULT` | 按故障类别查图案表（§5.3） |
| 4 | `LED_EFF_COMM_LOST` | **紫色 (128,0,128) 常亮** |
| 5 | `LED_EFF_ID_CONFLICT` | 1000ms 循环：0~333ms 粉 / 333~666ms 湖蓝 / 666~1000ms 紫 |
| 6 | `LED_EFF_BOOT` | 白色 (255,255,255)，300 ms 后由状态机切走 |
| 7 | `LED_EFF_REF_WARMUP` | **紫色 1 Hz 慢闪**（1000ms：亮 500 / 灭 500）——基线 EMA 热身着 |
| 8 | `LED_EFF_REF_PENDING` | **紫色 5 Hz 快闪**（200ms：亮 100 / 灭 100）——20 s 击打探测窗 |

`LED_EFF_COUNT = 9`。CAN `offset=0x6` 的 `0x04` 命令参数域是 `0~8`。

**队伍色**（`led_status.c:31`，与发射机构 `SHOOT_cmzy_REV081` 对齐）：

- 红队 = **粉** `RGB(255, 50, 100)`
- 蓝队 = **湖蓝** `RGB(0, 180, 255)`

**不要用纯红/纯蓝**——2026-09-09 专门修过这个。

**亮度**：P15，默认 **100%**，逐通道整数缩放 `value × brightness / 100`。

### 5.2 紫色三重含义——台架上最容易误判的一处

三种状态用**同一个紫色 (128,0,128)**：

| 现象 | 状态 | 含义 |
|---|---|---|
| 紫 **1 Hz 慢闪**（500/500ms） | `REF_WARMUP` | 基线 EMA 还在建立，还有 ≈10.5 s |
| 紫 **5 Hz 快闪**（100/100ms） | `REF_PENDING` | 在等第一记有效击打，有个 20 s 窗口；Flash 空时不会超时 |
| 紫 **常亮** | `COMM_LOST` | 电管 300 ms 没正确寻址本板了 |

**只靠闪烁频率区分**。`REF_WARMUP` / `REF_PENDING` 在状态机门控里优先级**高于** `COMM_LOST`，所以校准期间即使已经离线也是显示紫闪而不是紫常亮。

> **典型误判**：把一块没接电管的板单独上电，会看到 白 300ms → 紫 1Hz → 紫 5Hz → 紫常亮。**全程都是紫的**。最后那个紫常亮是"电管没在跟我说话"，不是校准没做完。如果此时 Flash 里有旧参考，校准其实已经在 ≈30.5 s 处按路径 ③ 正常结束了。

### 5.3 FAULT 分类图案（`Led_FaultRgb`，`led_status.c:64`）

按优先级 **超温 > 温窗 > PVD > SPI > 传感器** 取一个类别：

| 优先级 | 故障位 | 图案 | 周期 |
|---:|---|---|---|
| 15 | `FAULT_OVER_TEMP` | 粉红 `(255,50,100)` **常亮** + **PB0 亮** | 常亮 |
| 14 | `FAULT_TEMP` | 青 `(0,255,255)` | 200 ms（亮 100 / 灭 100） |
| 13 | `FAULT_POWER` | 白 `(255,255,255)` 单闪 | 500 ms（**亮 50 灭 450**） |
| 12 | `FAULT_SPI` | 琥珀 `(255,140,0)` | 500 ms（亮 250 / 灭 250） |
| 0~11 | 传感器类 | 粉 / 湖蓝交替 | 1000 ms（各 500） |

### 5.4 PB0 / PB1

两个都是**高电平点亮**（硬件实测确认，2026-08-21）。都在 20 Hz 网格上刷新，最坏 50 ms 显示滞后。

- **PB0 = 超温指示**：`Fault_GetBitmap() & FAULT_OVER_TEMP` 非零就亮，**任何状态下都有效**。
- **PB1 = 系统正常指示**：**仅当**当前灯效是 `NORMAL` / `HIT` / `ID_SETUP` 三者之一时亮。其余（BOOT、FAULT、COMM_LOST、紫闪校准）一律灭。

> PB1 灭 ≠ 坏了。校准期间 PB1 就是灭的。

## 6. 状态与持续时间

`sm_state_t`（`App/app/state_machine.h:20`），CAN 状态回复 `offset=0x5` 的 Byte0 即此值：

| 值 | 状态 | 进入条件 | 灯 | 持续 |
|---:|---|---|---|---|
| 0 | `BOOT` | 上电 | 白常亮 | **固定 300 ms** |
| 1 | `NORMAL` | 校准结束 / 自检通过 / 故障清除 / 通信恢复 / HIT 结束 | 队色常亮（PB1 亮） | 直到有事发生 |
| 2 | `HIT` | 触发并**确认通过**的击打 | 队色 5 Hz 快闪（PB1 亮） | **300 ms**（`SM_HIT_MS`），期间再次受击会刷新计时 |
| 3 | `FAULT` | `Fault_GetBitmap() != 0` | 分类图案，PB1 灭 | 直到位图清零（sticky 位只能靠自检通过或复位） |
| 4 | `COMM_LOST` | 300 ms 无合法本板请求（`BOARD_COMM_LOST_MS`） | 紫常亮 | 直到收到任一合法本板请求 |
| 5 | `ID_SETUP` | `StateMachine_OnIdSet(false)` | 队色 1 Hz 慢闪 | 1 s 后自动回 NORMAL。**当前无调用者，不可达** |
| 6 | `ID_CONFLICT` | `StateMachine_OnIdSet(true)` | 红蓝紫 333ms 循环 | 同上，**不可达** |
| 7 | `REF_PENDING` | 上电校准（见 §1） | 紫 1Hz / 紫 5Hz 两段 | ≈10.5 s + 20 s，或提前退出 |

### 6.1 校准期间受击会发生什么

`StateMachine_OnHitEvent()` 接受来自 `NORMAL` / `HIT` / **`REF_PENDING`** 三态的事件（`state_machine.c:279`）。

- 在 `REF_PENDING` 中受击 → 状态切到 `HIT`（队色快闪）、事件入 CAN 发送队列、串口打 `[HIT]`；
- **下一个 1 ms tick** 顶层校准门立刻把它拉回 `REF_PENDING`（因为还没训练完）；
- 队色只显示 ≤1 ms，而帧刷新是 20 Hz（50 ms 一次），**所以在台架上视觉上就是一直紫闪**，看不见那一下快闪。这是预期行为，不是灯坏了。

关于"上报 CAN"：事件先进一个**深度 4** 的 FIFO（`BOARD_HIT_QUEUE_DEPTH`），真正发出要等 `CanNode_IsReady()` 为真。所以**校准期间的击打会排队**，等电管枚举完本板后再以 100 ms 间隔依次补发。排队超过 4 条才开始丢（`s_hit_drop`）。

### 6.2 `HIT` 快闪期间再次受击

`state_machine.c:279` 对 `SM_STATE_HIT` 也接受，**刷新 300 ms 计时**（不重新开始也算，取刷新）。

### 6.3 FAULT / COMM_LOST 期间受击

不产生状态转移、**不发 CAN**，但仍然串口打日志、仍然计数。语义：可以观测到振动，但绝不能把它变成裁判系统的扣血。

## 7. 门控优先级

`StateMachine_Tick()` 每 1 ms 按这个顺序判（`state_machine.c:132`）：

```
① Fault_GetBitmap() != 0        → FAULT        （最高，≤1ms 响应）
② 非 BOOT 且 Sm_RefPendingNeeded() → REF_PENDING（校准是上电暂态，先完成）
③ s_comm_lost != 0              → COMM_LOST
④ 剩下的正常状态转移（BOOT/HIT/ID_* 的计时、清故障回 NORMAL）
```

由此推出的几条行为：

- **紫闪期间发生故障立刻转 FAULT**，故障图案优先显示；
- **掉线时若仍在校准窗口，仍然显示紫闪**——校准优先于显示离线；
- BOOT 的 300 ms 白灯**不被校准门打断**（"初始化之后再紫闪"）。

`StateMachine_OnCommLost()` 和 `OnHitEvent()` 会直接改 `s_state`，但都不检查是否处于 `FAULT`（前者检查了，后者没设 `s_state`）。真正的仲裁每毫秒在 `Tick()` 里重做一遍。

## 8. 台架判读速查

| 看到的现象 | 状态 | 下一步 |
|---|---|---|
| 白常亮 | BOOT | 等 300 ms |
| 紫 1 Hz 慢闪 | REF_WARMUP | 等，还有 ≈10.5 s。此期间敲打**不会**训练 |
| 紫 5 Hz 快闪 | REF_PENDING | 敲一记**真击打**。看串口是否出 `[CONF] trained` |
| 紫 5 Hz 闪了 >1 分钟不停 | REF_PENDING 卡住 | ① Flash 空（`HitDetect_RefValid()==0`）② 没有电管上线 ③ 击打全被 P27 拒了。看 `[CONF] rej corr=…` |
| 队色常亮 | NORMAL | 正常，可开打 |
| 队色 5 Hz 快闪 | HIT | 正常，300 ms 后回常亮 |
| 紫常亮 | COMM_LOST | 电管没在轮询本板，或 DLC 不对（§4.2） |
| 粉红常亮 + PB0 亮 | FAULT: 超温 | 查 TEMP |
| 青 5 Hz | FAULT: TEMP 出窗 | 查 REF5025 |
| 白单闪（亮 50/灭 450） | FAULT: PVD 欠压 | 看供电；sticky 位，每 5 s 自动重试自检 |
| 琥珀 2 Hz | FAULT: SPI/DRDY/ADC | 查采集链路 |
| 粉/湖蓝 500 ms 交替 | FAULT: 传感器 | 查某一通道的饱和/偏置/死通道 |
| 红蓝紫 333ms 循环 | ID_CONFLICT | **当前固件不可达**，见到说明代码被改过 |

### 8.1 串口关键日志（USART1 @115200 8N1）

```
[CONF] trained n=128 flash_err=0      训练完成并写 Flash（flash_err 0=成功）
[CONF] rej corr=NNN                   被 P27 拒（只留相关度，不产生事件）
[HIT] sum_peak=… p0=… p1=… p2=… p3=… I=NN% corr=NNN
[SELFTEST] PASS drdy=… / FAIL bits=0xNN …
[ADS] CLOCK after WREG: 0xNNNN        CLOCK 写入后回读（不判失败，供调试判读）
```

注意 `[HIT]` 里的 **`sum_peak` 实际是差分信号 `|dif_sum|` 的峰值**（`hit_event_t.peak` ← `dif_pk`），不是未差分的合力峰值。

### 8.2 Ozone 观察点

| 变量 | 含义 |
|---|---|
| `s_boot_samples` | 自 Init 起消费的样本数；热身门限 40960 |
| `s_warmup_samples` | 热身门限本身（`5 << s_bl`） |
| `s_ref_valid` | 有可用参考（Flash 载入 或 本次训练） |

## 9. 边界行为与已知取舍

1. **灯效相位用墙钟、判据用样本数**。两者起点差 <1 ms，仅丢帧时微偏（§1.1）。灯是给人看的，判据要严格——有意为之。
2. **热身期不判拒也不训练**。EMA 从 0 建立，前几个时间常数内冻结窗被沉降瞬态污染，`corr` 不可信。热身期击打照常计数上报，只是不算数（决策于 2026-10-16）。
3. **无参考时一律接受**。`s_ref_valid == 0` → `corr_q10` 恒为 0 → 若照常判拒会拒掉首击 → 训练永不可达 → 全新板永远训不出来。这是一个真实存在过的死锁，2026-10-17 修复。判据写成：
   ```c
   reject = (warmup_elapsed && s_ref_valid && P27 > 0 && corr_q10 < P27);
   ```
4. **P27 = 0 时只统计不判拒**，用于重采相关度分布做整定。
5. **`s_boot_samples` 饱和在 `0xFFFFFFFF` 不翻转**。
6. **训练失败不占用本次机会**：`Hit_RefTrain` 失败（`Hit_RefFix` 得到空窗）时不置 `s_ref_trained_boot`，下一记击打还可以再训。
7. **掉线计时自初始化起算**。板子上电后 300 ms 内若没被电管寻址，就会置 `COMM_LOST`——但因为校准门优先级更高，会先显示紫闪。这是"电管还没开始轮询"的正常表现，不是故障。
8. **参考样本只存合力，不存差分**。波形捕获保留的是未差分的 `hit_sum`，差分信号只用于触发。
9. **`Cal_Load` / `Cal_Save` 仍是 `TODO(Step 5)`**。参数无 Flash 持久化，每次上电回到 `Cal_GetDefaults()`。本文所有 P 参数都是编译期默认值。
